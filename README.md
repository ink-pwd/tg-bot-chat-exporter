# tg-exporter

Telegram-бот для выгрузки переписок из бесед поддержки за день: JSON и HTML-отчёт.

Бота добавляют в беседу (группу или супергруппу), и он сам сохраняет её сообщения. Беседа принадлежит тому, кто добавил бота: только этот человек видит её в боте, выгружает и отключает. В самой беседе бот ничего не пишет.

## Запуск

Нужны Docker и Docker Compose.

1. В [@BotFather](https://t.me/BotFather) создайте бота и **выключите privacy mode**: `/setprivacy` → бот → `Disable`. Без этого в группах бот видит только команды. Второй вариант — делать бота администратором каждой беседы. Если privacy mode меняли, когда бот уже был в беседах, его нужно добавить туда заново.
2. Скопируйте `.env.example` в `.env` и заполните:
   - `BOT_TOKEN` — токен от @BotFather;
   - `MESSAGE_ENCRYPTION_KEY` — ключ шифрования сохранённых сообщений:
     ```bash
     python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
     ```
     **Храните ключ отдельно от базы.** Если его потерять, сохранённую историю бесед будет не прочитать;
   - `MESSAGE_RETENTION_DAYS` — сколько дней хранить сообщения (по умолчанию 7: в боте можно выгрузить сегодня и 6 предыдущих дней);
   - `MYSQL_*` — пароли для MySQL;
   - `ALLOWED_USER_IDS` — по желанию: id пользователей Telegram, которые могут пользоваться ботом и подключать беседы.
3. Запустите:
   ```bash
   docker compose up -d --build
   docker compose logs -f bot
   ```
   Миграции базы применяются автоматически при старте бота.

### Сервер с 1 ГБ RAM

Конфигурация рассчитана на маленький сервер. MySQL урезан по памяти (буфер 64 МБ, без `performance_schema`), у каждого контейнера свой лимит: бот 550 МБ, MySQL 400 МБ, Redis 64 МБ. Лимит — это потолок, а не резерв. Реально в работе: бот ~320 МБ, при выгрузке до ~400, MySQL ~125 МБ, Redis ~8 МБ.

- Если контейнер упал или превысил лимит, Docker перезапускает только его, остальные продолжают работать.
- Чтобы контейнеры поднимались после перезагрузки сервера, служба Docker должна быть в автозапуске: `sudo systemctl enable docker`.
- Swap на 1–2 ГБ нужен как страховка от нехватки памяти.
- Если собираете образ прямо на сервере, после сборки освободите диск: `docker builder prune -f`.

## Логи

Логи пишутся в консоль (`docker compose logs bot`) и в папку `./logs`, отдельный файл на каждый день: `2026-10-05.log`, `2026-10-06.log` и т.д. Дата и время в логах — по UTC. Файлы старше `LOG_RETENTION_DAYS` дней (по умолчанию 30) удаляются автоматически.

Тексты сообщений и ключи в логи не попадают.

## Подключение беседы

В боте: «➕ Добавить в беседу» → выберите группу. Можно добавить бота и обычным способом, через участников группы. Бот пришлёт в личку подтверждение. Если он видит в беседе только команды, придёт и предупреждение про privacy mode.

- **История до добавления бота недоступна.** У Bot API нет доступа к прошлым сообщениям, поэтому бот сохраняет беседу с момента, когда его добавили.
- Если бота удалили из беседы, новые сообщения перестают сохраняться, а старые остаются в выгрузках. Беседа помечается ⚠️ в «Мои беседы».
- Если после удаления бота снова добавит **другой** человек, сохранённая история удаляется. Новый владелец получает только то, что придёт при нём.
- «Мои беседы» → беседа → «Отключить и удалить сообщения»: бот выходит из беседы и удаляет всю её историю.
- Когда группа становится супергруппой, история сохраняется.
- Если задан `ALLOWED_USER_IDS` и бота добавил кто-то не из списка, бот сразу выходит из беседы.

Сообщения хранятся в MySQL. Текст, имя отправителя и источник пересылки зашифрованы. Сообщения старше `MESSAGE_RETENTION_DAYS` дней удаляются автоматически.

## Выгрузка

В главном меню: «📥 Выгрузить». Откроется список из 7 дней, от сегодня до шести дней назад. Бот присылает в личку JSON-файл и отчёт по всем вашим беседам, в которых за этот день были сообщения. Если за день в базе ничего нет (бот ещё не был в беседах или сообщений не было), бот так и отвечает и пустые файлы не присылает. Границы суток считаются по часовому поясу пользователя: его выбирают в «⚙️ Настройки → Часовой пояс». Пока пояс не выбран, используется `DEFAULT_TIMEZONE` (по умолчанию `Europe/Kyiv`).

В Redis кешируется ссылка на уже отправленный файл (`file_id`) и счётчики. Повторный запрос за прошедший день в течение 24 часов бот отвечает мгновенно. Для сегодняшнего дня кеш живёт 10 минут, а кнопка «Обновить» собирает день заново. Пустой результат не кешируется: сообщение, пришедшее позже, сразу попадёт в выгрузку.

Файлы больше 20 МБ отправляются сжатыми (`.json.gz`). Одновременно собирается не больше `EXPORT_CONCURRENCY` выгрузок (по умолчанию 3).

## Отчёт по поддержке

К каждой выгрузке, ручной и автоматической, прикладывается HTML-отчёт: оба файла приходят одним альбомом. Отчёт оформлен как годовой отчёт по поддержке Dots, но за один день. Он открывается в браузере, работает офлайн и поддерживает светлую и тёмную тему. Пока выгрузка собирается, бот показывает шкалу с этапами: сбор сообщений → анализ → формирование и отправка файлов.

Что в отчёте:
- **Ключевые цифры:** обращения, уточнения и напоминания; медиана и 90-й перцентиль первого ответа; доля ответов за 15 минут в рабочее время; вопросы без ответа на конец дня; доля сообщений вне рабочего времени (рабочее время — Пн–Пт 09:00–20:00).
- **Категории и топ запросов** — по классификации поддержки Dots (14 категорий, 90 типов), со стандартным ответом на каждый тип и реальными формулировками клиентов.
- **Прочие темы** — обращения, которые не удалось отнести к типу, сгруппированные по смыслу.
- **Время ответа:** распределение и доля ответов за 15 минут по часу, когда написал клиент.
- **Сообщения по часам, таблица по беседам, самые долгие ожидания.**

Определения:
- **Обращения** — новые запросы клиентов: вопрос, просьба, скриншот или файл без подписи. Несколько сообщений подряд с паузой до 2 минут и без ответа поддержки между ними считаются одним вопросом. Для анализа берётся только сам запрос, без приветствия и вступления.
- **Уточнения** — реплики, которые продолжают прошлый запрос того же клиента. Это ответ через reply, «а если…», «не получилось», вопрос без своей темы или на ту же тему в течение 2 часов. «Ещё вопрос», «и ещё…» всегда открывают новый запрос.
- **Напоминания** — «вы тут?», «есть новости?» без другого текста. Список фраз закрыт намеренно: лучше пропустить напоминание, чем потерять настоящий запрос.
- **Время ответа** — от вопроса клиента до первого ответа поддержки по существу. Приветствия и «секунду, уточню» ответом не считаются.

Телефоны, почта, пароли и токены в цитатах отчёта маскируются. JSON-выгрузка остаётся полной.

### Классификация запросов

Тип запроса определяет модель (TF-IDF + логистическая регрессия), обученная на размеченных вопросах из годового отчёта по поддержке. LLM не используется: на одном и том же тексте модель всегда даёт один и тот же ответ. На отложенных примерах тип определяется примерно у 40% запросов, и из них ~80% верно. Если модель не уверена, обращение уходит в «Прочие темы».

- Названия категорий и типов и стандартные ответы лежат в `src/infrastructure/nlp/resources/taxonomy.toml`.
- Модель лежит в `intent_model.npz` рядом. В файле только словари признаков и веса, текстов переписок там нет.
- Переобучение, например на новом годовом отчёте или после правок словарей:
  ```bash
  python scripts/train_intent_model.py --report "Dots Support Report.html"
  ```
  Отчёт с перепиской клиентов в репозиторий не кладите: файлы `*.html` и `*.json` в корне проекта игнорируются git.

«Прочие темы» группируются по словарю понятий `src/infrastructure/nlp/resources/concepts.toml`, где синонимы на русском и украинском сводятся к одному понятию. Стоп-слова и вежливые фразы лежат рядом, в `stopwords.txt` и `fillers.txt`. После их правки модель типов нужно переобучить.

## Автовыгрузка

В главном меню: «⏰ Автовыгрузка», где можно выбрать время или выключить её. Каждый день в это время (по часовому поясу пользователя) бот присылает выгрузку всех ваших бесед за прошедший день.

- Если бот был выключен в нужное время, после запуска он выгрузит пропущенный день. При долгом простое выгружается только последний день, остальные можно выгрузить вручную, пока они в пределах 7 дней.
- Если за день сообщений не зафиксировано, приходит короткое уведомление без файлов.
- При сбое бот делает до 3 попыток с паузой 5 минут, потом сообщает об ошибке. Этот день можно выгрузить вручную.
- Если пользователь заблокировал бота, автовыгрузка выключается.
- При смене часового пояса бот спрашивает, менять ли время автовыгрузки. Если не менять, время остаётся тем же, но уже по новому поясу.

## Структура

```text
src/
├── domain/          сущности и правила, без внешних библиотек
├── application/     сценарии (use cases) и интерфейсы
├── infrastructure/  MySQL (SQLAlchemy), Redis, Bot API, шифрование, NLP, конфиг
│                    (+ scripts/ — обучение модели типов запросов)
├── presentation/    хэндлеры и клавиатуры aiogram
└── main.py          сборка зависимостей и запуск
migrations/          миграции Alembic
```
